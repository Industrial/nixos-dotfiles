# Anduril NixOS STIG — control triage

Anduril NixOS Security Technical Implementation Guide **V1R3** (30 Sep 2026) — 103 controls, 11 CAT I / 91 CAT II / 1 CAT III.

Generated by `bin/stig-triage-gen` from
`features/security/stig/data/Anduril_NixOS_STIG-V1R3.controls.json`. Id, severity and
requirement text are mechanical. **Class, target and note are hand-annotated and are a
review proposal, not verified ground truth** — the `disruptive` judgements in particular
are read off each control's fix text, not from having applied it to a host.

## Taxonomy

| Class | Meaning | Target |
|---|---|---|
| `zero-cost` | No user-visible change on a desktop daily driver | `profiles/base-safe.nix` → `profiles/base.nix` |
| `disruptive` | Changes interactive behaviour, or needs site infrastructure that does not exist yet | `profiles/full.nix` only — never the four desktops |
| `n-a` | Not applicable to this fleet; needs a written justification in the report | excluded via `security.stig.exclude` |

## Open questions for review

1. `V-268144` (encryption at rest, CAT I) needs a per-host answer — the four `hosts/*/disko.nix`
   layouts have not been audited for full-disk encryption yet.
2. The six PKI/MFA/directory controls (`V-268124`, `V-268125`, `V-268135`, `V-268136`,
   `V-268177`, `V-268179`) all presuppose identity infrastructure. `features/security/yubikey`
   is the only existing basis. Decide whether to build toward them or exclude them as a group.
3. `V-268101` / `V-268102` need a real notification destination before they mean anything.
4. Two controls are classified `n-a` (`V-268079`, `V-268180`). Both are procedural rather than
   configurable; confirm the justifications hold.
