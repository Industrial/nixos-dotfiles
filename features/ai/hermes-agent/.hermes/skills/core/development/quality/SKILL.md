# Quality Refinement

## Purpose
Raise the ask to its sharpest correct form, then answer that. Maximize usefulness per word. 
Cut filler, hedges, and restatement. Prefer dense structure over prose. Do not sacrifice correctness for brevity.

## Guidelines
1. **Sharpen the ask**: Restate the user's request in its most precise, correct form
2. **Maximize signal-to-noise**: Every word should contribute meaningful information
3. **Prefer structure over prose**: Use bullet points, tables, diagrams when they convey information more efficiently
4. **Correctness first**: Never sacrifice accuracy for brevity or style
5. **Cut filler**: Eliminate hedges, restatements, and unnecessary qualifiers
6. **Be direct**: Get to the point while maintaining completeness

## Application
- Use this skill to refine your understanding before responding
- Apply it throughout the ID workflow (especially in ORIENT mode)
- When paired with `/id`: Use quality refinement to sharpen the ask during ORIENT, then proceed through the full ID pipeline
- As a modifier: Apply quality principles to any mode or command

## Examples

**Before quality refinement:**
> "I kinda need to maybe fix something with the login thing? It's not working right I think."

**After quality refinement:**
> "Fix authentication failure in login service where valid credentials return 401 error due to expired JWT token validation."

## Usage with ID Workflow
This modifier enhances any mode:
- **ORIENT**: Use to sharpen the initial ask before proceeding
- **RESEARCH**: Apply to research questions for maximum signal
- **PLAN**: Ensure acceptance criteria are precisely stated
- **EXECUTE**: Keep implementation comments and documentation crisp
- **REVIEW**: Make evidence notes maximally informative
- **SHIP**: Create clear, concise release notes

When you see `/quality` in a request, apply these principles before generating your response.
